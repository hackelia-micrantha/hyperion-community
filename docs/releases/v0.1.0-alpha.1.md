# Hyperion Community v0.1.0-alpha.1 — candidate release notes

**Status: draft, not tagged or published.** This document describes the proposed first public source-level alpha. The final release identity, source commit, publication date and verification receipts must be established by the release owner after the separate approval and release-readiness gates. It does not describe an existing downloadable release.

## What this alpha contains

This is a deployment-neutral, Apache-2.0 public reference slice:

- **OpenTofu/Terraform:** a provider-free synthetic reference-environment module, plus an Incus-instance module with a credential-free `lxc/incus` provider-schema validation example. The Incus example uses the committed provider lock and `-lockfile=readonly` for initialization.
- **Ansible/K3s:** a fail-safe bootstrap role that defaults to no installation; optional binary acquisition checks the exact release and architecture-specific upstream SHA-256 first.
- **Kubernetes/Kustomize:** a synthetic restricted workload, ServiceAccount, Service and NetworkPolicies, with a local overlay that can be rendered and schema-validated without a cluster.
- **Flux:** documentation for consuming a reviewed public Git commit immutably. The public suite does not bootstrap or reconcile a real cluster.
- **Validation:** reproducible `mise` tasks for source linting, OpenTofu validation, Ansible check mode, Kubernetes schema checks, publication-boundary tests, Trivy and Checkov.
- **Website:** static HTML/CSS source. A hosted site or preview deployment is not part of the release contract.

No private infrastructure configuration, environment state, credentials, encrypted deployment material or private Git history is part of this distribution.

## Supported verification path

The public source contract is validated on **Ubuntu 24.04 in hosted GitHub Actions**. Other developer operating systems and live deployment environments are not qualified by that evidence.

After publication, use the **approved immutable release tag or source commit**, rather than a floating branch:

```sh
git clone https://github.com/hackelia-micrantha/hyperion-community.git
cd hyperion-community
git checkout <approved-tag-or-40-character-commit-sha>
mise install
mise run doctor
mise run lint
mise run ci
```

This is a read-only/public-fixture verification path with respect to external infrastructure. It can download pinned development tools and public provider/dependency packages, and creates local build/validation files. It does not run `tofu apply`, provision Incus, install K3s on a host or connect to a production cluster. Use a disposable checkout for verification.

## Compatibility and limitations

This **alpha** is an inspectable source/contract preview, not a supported production infrastructure distribution. In particular:

- The Incus example proves provider-schema compatibility, **not** `plan/apply/destroy`, instance lifecycle or a consumer's deployment compatibility.
- The K3s role's default is non-mutating. Binary acquisition is an opt-in primitive, **not** server/agent installation, upgrade, cluster readiness or rollback qualification.
- Kustomize fixtures and security controls are synthetically rendered; there is no live-cluster admission or policy-enforcement proof.
- Flux guidance shows immutable-source pinning but has no disposable reconciliation or live bootstrap qualification.
- No production environments, configuration migration, backup/restore, observability or uptime are supported here.
- No `hyperctl` binary, man page, completions or public Nix package is shipped in this source alpha.
- API/schema stability across future pre-1.0 revisions is not guaranteed. Consumers must pin exact revisions and review compatibility before updating.

Runtime K3s lifecycle, Flux reconciliation and private integration cutover require separately reviewed evidence; they are not silently included in this release.

## Integrity, updating and rollback

The intended release artifact is the public repository **source tree at one immutable, approved Git tag/commit**. There is no application binary or container image built by this release.

Before publication, the release owner must record the final commit/tag, validate the exact candidate, review the public archive contents, and publish source identity and any applicable archive checksums in the release record. A passing CI run on an earlier commit is not evidence for a changed release candidate.

Consumers should pin the reviewed release commit and update by explicitly selecting a newer reviewed commit/tag, rerunning the public verification tasks and checking component compatibility. Reverting to the previous pinned commit restores only the **public source input**; it does not roll back any infrastructure a consumer may have independently provisioned. Any such infrastructure is the consumer's operational responsibility.

## Before these notes may be published as a release

The release owner must finish exact-candidate CI, fresh-clone consumption, security/publication and licensing review, and source/archive integrity verification; record any unresolved alpha disclosures; and obtain explicit tag/publication approval. After publication, verify the tag resolves to the accepted commit, the source archive is accessible without private credentials, the documented commands work from a clean checkout, and the release record contains the immutable identity and checksums where applicable.
